# 01_EXPERIENCE — Tattava Copilot

This integrated V1 experience package contains:

1. `01_User_Flows.md` — end-to-end journeys, alternate paths, exceptions, recovery and traceability.
2. `02_UX_Specification.md` — information architecture, screen inventory, interface behaviour, state models and accessibility.
3. `03_AI_Interaction_Specification.md` — user-visible AI behaviour, context, uncertainty, research, candidate generation, human review and failure handling.
4. `04_Design_System.md` — component conventions, provisional visual tokens, AI-specific patterns and accessibility rules.

## Governing product principle
**Make the project itself intelligent.** The project is the primary context; conversation is one interaction surface. AI prepares and recommends; authorised humans own consequential creative decisions and Canon updates.

## Source alignment
Prepared against the accessible BRD, Product Strategy, updated PRD, product-scope materials and supporting experience/architecture findings. Strategy and updated PRD govern where older material conflicts. Product requirements are distinguished from provisional visual recommendations and open policy decisions.

## Delivery status
These are implementation-oriented documentation baselines, not claims that final visual wireframes, approved brand assets, a production interface, or validated usability results already exist. Visual tokens are provisional pending brand review. Action-level permissions, provider policy, retention, source hierarchy, file limits, KPI thresholds and operational details remain explicit open decisions.

## Final refinement layer

This package preserves the current four-document experience baseline and adds a final refinement layer focused on implementation hand-off:
- Stable screen IDs and screen-to-requirement acceptance mapping.
- Low-fidelity structural wireframes for core V1 journeys.
- Additional journey and edge-state coverage.
- Observable AI-to-UX contracts and evaluation scenarios.
- Semantic component contracts for evidence, candidates, decisions, Canon, status and recovery.
- Explicit open decisions where source evidence does not establish a final policy or design choice.

The wireframes are intentionally low fidelity. They specify hierarchy and behaviour rather than claiming approved brand design or production UI. Requirements and design recommendations remain distinct, and unresolved action-level permissions, package rules, file limits, visual standards and evaluation thresholds remain open.

## Final package review checklist

- [ ] Product Strategy, PRD, BRD and scope boundaries reconciled.
- [ ] Screen IDs mapped to journey steps and acceptance evidence.
- [ ] Core screens include loading, empty, partial, blocked, stale, error and recovery states where relevant.
- [ ] AI-generated content is distinct from approved content and Canon.
